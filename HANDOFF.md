# Handoff — vishnumuthiah.com + optionsvision.app

Last updated 2026-07-24.

## What this is

**One Cloudflare Worker (`vishnu-muthiah-portfolio`, `worker.js`) serves two sites**, split on
`url.hostname` at the top of `fetch`:

| Host | What it is | Theme |
|---|---|---|
| `vishnumuthiah.com` | personal portfolio | light |
| `optionsvision.app` | OptionsVision product site | navy (matches the app) |

`optionsvision.app` was registered 2026-07-24 on Cloudflare Registrar. `.app` is HSTS-preloaded,
so it is HTTPS-only always. **Both** custom domains are declared in `wrangler.jsonc` routes, so a
deploy can never leave the portfolio binding unasserted.

### Routes

```
optionsvision.app     /                                        product page
                      /support  /privacy-policy
                      /terms-of-service  /disclaimer           OptionsVision's own (generated)
                      /.well-known/apple-app-site-association   Universal Links
                      /p/<payload>                             share fallback page
                      anything else                            301 -> /

vishnumuthiah.com     /                                        homepage
                      /optionsvision                           engineering CASE STUDY
                      /tradevision                             301 -> /optionsvision
                      /support  /privacy-policy
                      /terms-of-service                        ⚠️ SOURCES TRACKER, not the app
                      /sources-tracker                         Slides add-on page
```

> **Trap:** the portfolio's `/support`, `/privacy-policy` and `/terms-of-service` document the
> **Sources Tracker Google Slides add-on**. They have nothing to do with OptionsVision. Never route
> them onto the app host — App Store Connect points at the `optionsvision.app` ones.

## Deploy workflow (automatic — user opted in, don't ask)

```bash
cd ~/Developer/vishnuamuthiah.com && node --check worker.js && npx wrangler deploy --dry-run
git add -A && git commit -m "..." && git push && npx wrangler deploy
```

Report the **Version ID** every time. Rollback: `npx wrangler rollback`.

There is a **second deploy target** — the legacy share host, a Cloudflare **Pages** project:

```bash
cd ~/Developer/TradeVision && npx wrangler pages deploy web --project-name=tradevision-web --branch=main
```

(If npm throws EACCES/EEXIST, prefix with `npm_config_cache="$HOME/.npm-wr-cache"`.)

A `git push` may also trigger a Workers Builds CI deploy of the same code. Harmless.

## Generated files — never hand-edit

| File | Generated by | Source of truth |
|---|---|---|
| `legal-content.js` | `tools/extract-legal.py` | app's `TradeVision/LegalView.swift` |
| `share-page.html` | `tools/sync-share-page.py` | app's `web/p/index.html` |
| `tradevision/og-card.png` | `tools/rasterize-pdf.swift` + `tools/flatten-navy.swift` | `tradevision/og-card.pdf` |

The legal pages exist so App Store Connect's privacy URL says what the app says. Edit the **Swift**,
re-run the script, redeploy. The Privacy Policy interpolates `TradeShare.host`, so changing the
share domain changes the legal copy automatically — that is by design.

Regenerate the OG card after a new PowerPoint → PDF export:

```bash
swift tools/rasterize-pdf.swift tradevision/og-card.pdf tradevision/og-card.png 1200 630
swift tools/flatten-navy.swift tradevision/og-card.png tradevision/og-card.png
```

## Theming: tokens, not a fork

Every colour in `getSharedStyles()` and `getLegalPageStyles()` reads a CSS variable whose `:root`
default is the portfolio's original palette. `getAppThemeStyles()` redefines those same names with
the app's `Theme.swift` values and is injected by `getLayout` **only when `meta.app` is true**.

```
launchNavy #0E1B33 · wellFill #16233F · boxFill #1A263D
accent #6BCCF5 · gold #D9AE57 · off-white #EBE6DA
```

**To restyle either site, change tokens. Do not add hex literals.** A handful of carousel/CTA
surfaces are still literal and are restated inside `getAppThemeStyles()`; they are commented.

## Universal Links — the rules that don't bend

New share links are built on `optionsvision.app`. Links shared before 2026-07-24 were built on
`tradevision-web.pages.dev` and **are out in the world permanently**.

- `tradevision-web.pages.dev` stays in `TradeShare.legacyHosts`, stays in the `applinks:`
  entitlement, and keeps serving both its AASA and its `/p/` page. **Forever.** Removing any of
  those breaks links real people already sent each other.
- `TradeVisionTests/TradeShareTests.swift` guards this. If `legacyHostLinksStillOpen` fails, that
  is a real regression, not a test to update.
- After editing the share page, deploy **both** hosts (sync script, then both deploy commands).

### Per-trade link previews

`optionsvision.app/p/<payload>` decodes the trade server-side and writes a headline naming it
(`AAPL $227.50 Long Call · Aug 15`). The payload is **attacker-controlled input rendered into an
HTML attribute** — symbol and strategy are *validated against their real shapes*, not scrubbed of
bad characters, because scrubbing `"><script>alert(1)</script>` leaves `SCRIPTAL`, a plausible
headline built from an attack string. Anything that fails validation falls back to the generic
card. Keep it that way. No P&L in the headline: that needs the pricing engine, and a number that
contradicts the chart the page draws is worse than no number.

The legacy Pages host is static and keeps the generic card. That's fine — new links use the new
domain.

## Open items

1. **The app has not shipped with the new host.** `TradeShare.host` and the entitlement changed,
   but until an App Store release goes out, installed apps don't know about `optionsvision.app` —
   new links they receive open the web page instead of the app. Old links work throughout.
2. The OG card image still reads "Your Robinhood options companion" while the headline says "See
   any options trade before you place it". The user considers these complementary. Robinhood is a
   third-party trademark and the app's own disclaimer says it is not affiliated with any broker —
   flagged, user's call, already made.
3. `og:description` doubles as the page's `<meta name="description">`, so it is also the Google
   snippet. Currently optimised for link previews (93 chars). Split them if search traffic matters.
4. `edit-trade.png` and `launch-screen.png` in `tradevision/` are referenced nowhere.

## Gotchas hit this session

- **The app's Xcode scheme is missing its `<Testables>` block** in the user's working tree, so
  `xcodebuild test` fails with "not configured for the test action". Restore it to run tests, then
  put their version back byte-identical.
- `wrangler dev` doesn't honour a `Host:` header for hostname routing, so the two-site split can't
  be exercised locally that way. Test the pure functions in Node with a shim instead.
- A failed heredoc script **does not stop a `node ... && git ... && wrangler deploy` chain on the
  next line**. That shipped a broken `og:image` reference once. Put the whole thing in one `&&`
  chain, or check before deploying.
- Cloudflare edge propagation lags a few seconds after deploy; a route can 200 when it should 301
  if you curl immediately. Re-check with a cache-buster before believing a failure.

## Boundaries

Don't handle the user's Cloudflare API token or password (they `wrangler login`). App Store Connect
changes are theirs. Flag anything genuinely destructive before doing it.
